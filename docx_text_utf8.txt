RA Requirements for Multi-Agent Research Web Interface1. GoalBuild a web interface on top of the existing Python multi-agent simulation codebase for two types of studies:Pure AI Teams ΓÇö simulations in which all team members are AI agents.AI Teams with Human-in-the-Loop ΓÇö experiments in which a human participant observes and interacts with an AI team.The web application should call the existing Python codebase rather than reproduce simulation logic in the front end.(The code base is adapted from: https://github.com/apappu97/multi-agent-teams-hold-experts-back, for paper:┬áMulti-Agent Teams Hold Experts Back (arXiv:2602.01011) - A toolkit for multi-agent LLM teamwork experiments)The project should support the four interdependence structures specified in the current research planΓÇöpooled, sequential, reciprocal, and teamΓÇöand save task scores, token usage, and conversation transcripts. Most of the data storing steps are implemented in the existing Python codebase.Source: Saavedra, R., Earley, P. C., & Van Dyne, L. (1993). Complex interdependence in task-performing groups.┬áJournal of applied psychology,┬á78(1), 61.2. First Step: Choose Experiment TypeOn the landing page, the researcher creates a new experiment. The first choice is:Option A ΓÇö Pure AI TeamAI agents complete the task without human participation.Option B ΓÇö AI Team + Human-in-the-LoopA human participant observes the AI team and can intervene during the interaction.These should lead to two separate researcher configuration pages/workflows.The two workflows can share backend components such as:tasks;LLM configuration;agent configuration;interdependence structures;scoring;data storage.However, participant and intervention settings should appear only in the Human-in-the-Loop workflow.3. Running ExperimentsExperiments should run on the server side, not depend on the browser remaining open.For Pure AI simulations, show progress such as:47 / 100 simulations completedAlso show:running;completed;failed;cancelled.For Human-in-the-Loop studies, show participant-session status such as:not started;active;paused;completed;disconnected;terminated.Errors should be saved rather than causing completed data to disappear.6. Researcher Results DashboardAfter or during an experiment, researchers should see a simple dashboard.At the top of the page, provide two clear buttons:Download DataView Individual Runs/ SessionsThe dashboard shows the following statistics, which will be returned by the Python backend (do not need JavaScript to calculate them).PerformanceFor scoring tasks with the right answer, show:mean scoremedianstandard deviationminimum/maximumscore distributionEfficiencyShow:input tokensoutput tokenstotal tokensconversation turnsrun durationReliabilityShow variation in performance across repeated simulations.The dashboard should provide quick descriptive results rather than attempt to replace statistical analysis in R/Python/Stata.7. Individual Run / Session ViewerResearchers should be able to open any individual run or participant session. This data can be accessed from a json or csv file.Display:taskmodelnumber of agentsinterdependence structureroundsfinal answertask scoretoken usagefull conversation transcriptClearly label messages from:Agent 1Agent 2Agent 3, etc.Human ParticipantSystemFor Human-in-the-Loop studies, human messages must remain clearly distinguishable from system prompts.8. Participant InterfaceThe participant-facing page should be simple and separate from the researcher interface.StartParticipant opens a unique session link and sees:experiment instructionsBegin buttonUse participant/session IDs rather than names whenever possible.Observe AI TeamDisplay the AI team's conversation as it happens, paced for human readers such that the participant has enough time to read and respond.Show:speakermessagecurrent roundwhether the team is running or pausedNew AI messages should appear without requiring a page refresh.PauseProvide:Pause TeamPause should happen at a safe boundary. If an LLM request is already running, it may finish, but the system should not begin another AI turn.Intervene [PENDING: the possible interventions will depend on what  the backend looks like]When paused, the participant can type:instructions;clarification;new information;questions;corrections;suggestions.Then click:Send to TeamSend to Agent 1Send to Agent 2Send to Agent 3Etc.The human message should appear in the conversation.ResumeProvide:Resume TeamThe AI team should continue from the existing conversation rather than restart.CompletionAt the end:save the final team answer;save the score;save all messages;mark the session complete;show a completion screen.Refreshing or temporarily disconnecting should not restart or erase the participant's session.9. Data DownloadProvide a clear:Download Databutton.Recommended export:runs.csvmessages.csv or messages.jsonlhuman_interventions.csvconfig.jsonResearchers should be able to download the complete raw dataset, not only dashboard summaries.API keys must never appear in downloadable files.11. Backend ArchitectureRecommended structure:Researcher / Participant BrowserΓåÆ Web Backend / APIΓåÆ Existing Python Simulation CodeΓåÆ LLM ProviderThe backend should manage:experiment configuration;simulation jobs;participant sessions;pause/resume;interventions;persistent storage;results;data export.The server, not browser JavaScript, should maintain the authoritative experiment/session state.12. SecurityAt minimum:researcher loginresearcher/participant role separationsecure API-key handlingAPI credentials not storedHTTPS in deployment?participant-session isolationserver-side input validationParticipants must never be able to access:researcher controls;other participant sessions;API credentials;hidden experimental information;downloadable research datasets.13. Important Decisions the Research Team Must MakeWhen may participants intervene?Who receives a participant's intervention?Does the LLM see it as a system instruction, user message, or human teammate message?Does a human intervention count as a conversational turn?What happens immediately after an intervention?Can participants see all AI-agent communication?Can participants terminate the experiment early?These choices affect the experimental treatment and therefore should be decided by the research team.14.
